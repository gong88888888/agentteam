# 自适配前端优化方案

## 目标与边界

以资深前端工程实践为标准：先保证任务可完成、状态可信、数据不丢，再优化响应、可访问性和视觉一致性。自适配是根据产品、技术栈、容器和任务风险选择策略，不是自动改主题，也不是承诺任何页面零缺陷。

本次交付为可复用方案、Skill 和独立代码库，不修改现有 PPT 自动审核的未完成改动，不代表 PPT 生成链路已经验收。当前页面指对话中的创作中心/PPT 重建页面，并结合本地组件源码分析；旧截图不能证明当前运行效果。

## 本项目提炼的规则

以下路径相对于项目根目录，仅用于追溯，不是其他项目的依赖。

| 证据 | 通用规则 | 本项目下一步 |
| --- | --- | --- |
| frontend/package.json 使用 Vue3、Element Plus、Pinia、Vite | 保持既有框架和组件体系，避免双套 UI/状态源 | 复用现有图标、表单、弹窗和主题变量 |
| PptReconstructionPanel.vue 的 min-width:0 与 minmax(0,1fr) | 子容器也必须允许收缩，不能靠 body overflow:hidden 掩盖问题 | 检查展开侧栏、长文件名、错误日志和缩略图栏 |
| 同组件的 template-pages 有意横向滚动 | 合理滚动与裁切缺陷分开报告 | 缩略图可滚动，主要操作与错误信息不可被截断 |
| 同组件使用 Object URL | 资源由创建者负责释放；切换任务时拒绝过期结果 | 覆盖预览快速切换与卸载测试 |
| useTaskStream.js 的缓冲、节流、活动门控、序号去重、预览上限、卸载清理 | 流式传输与 DOM 刷新解耦 | 复用已有 composable，不再实现第二套 SSE |
| 改进思考与法则.md 的 Vue 动态图标与行为测试经验 | 图标传组件引用；测试用户行为，不只搜源码 | 覆盖按钮可用状态、实际事件与响应结果 |
| 用户无法理解审核计划 JSON | 内部协议不应成为普通用户的操作前提 | 自动生成与审核；失败给出原因、修复入口和诊断下载 |
| 对话中的裁图偏移与 QA 错误 | 视觉正确、坐标正确、业务成功是不同验收维度 | 图片像素坐标不混入 CSS 布局坐标；前端不伪造 QA 成功 |

## 规则矩阵

| 维度 | 默认策略 | 例外与判定 |
| --- | --- | --- |
| 产品布局 | 工作台使用无装饰分区、紧凑标题、稳定导航 | 仅营销任务使用 hero；编辑器优先主画布 |
| 控件 | 图标用既有库；图标按钮有名称和 tooltip；模式用分段/选择框 | 文本按钮用于明确命令，不把所有配置做成按钮 |
| 响应式 | Grid/Flex 子项 min-width:0；长文本换行；媒体固定比例 | 表格/时间轴可局部滚动，必须可发现、可键盘操作 |
| 视觉 | 复用语义 token、状态不只靠颜色、不嵌套装饰卡片 | 品牌已有规则优先；新增卡片圆角通常不超过 8px |
| 字体 | 固定字号阶梯、行高随用途、字距不取负值 | 不按 viewport 缩放字号；200% 文字缩放时允许布局重排 |
| 异步 | 单一状态源；旧请求不得覆盖新结果；卸载清理 | 写操作采用幂等键/任务 ID，对账后再重试 |
| 状态 | idle/loading/empty/error/success 可辨认，错误可恢复 | 长任务显示真实阶段；没有进度数据不编造百分比 |
| 性能 | 先测首屏、交互、长列表、流式刷新和包体 | 有证据再懒加载/虚拟化；不为微优化新增缓存层 |
| 可访问性 | 原生语义、键盘、可见焦点、表单标签、状态播报 | 自动探针不是完整 WCAG 审核，需人工辅助技术验证 |

## 分阶段落地

1. 基线：记录路由、角色、主题、容器尺寸、主要动作及失败路径；采集截图、控制台错误和相关测试结果。耗时/包体无数据时标记待测。
2. 正确性：自动审核移除手工 JSON 前提；把预检、审核、生成、QA 和交付状态绑定真实任务结果；输入变更使旧审核失效；服务端保留严格校验。验收包含失败恢复、重复点击、切换任务与刷新恢复。
3. 布局与交互：侧栏展开/收起、320/390/768/1440px 宽度和嵌入式窄容器下走完整流程；检查长路径、中英文、空列表、十倍数据、键盘和文字放大。不能只检查 document.scrollWidth。
4. 性能与沉淀：复用 useTaskStream/useManagedEventSource；按路由记录构建产物与加载成本；有瓶颈再做拆包或虚拟化。抽取已出现至少两次且语义相同的组件，不建立万能业务组件。

每阶段小范围提交，可独立回滚。性能预算需根据本项目基线和目标设备约定，不把某个毫秒值强制套用所有页面。外部 API 失败、网络断开、权限不足都应保留输入并提供可执行的下一步。

## 通用能力与架构

```text
业务页面（用户目标、领域文案、权限）
  -> 任务编排（状态、取消、重试、失效）
  -> 既有设计系统（token、控件、布局、可访问性）
  -> 平台适配（请求、事件流、存储、资源清理）
横向验证：行为测试 + 浏览器检查 + 性能基线 + 人工验收
```

本 Skill 的代码资产只覆盖跨框架的最新结果控制、URL 生命周期、容器布局与溢出探针。路由权限、上传鉴权、SSE 重连和 QA 业务规则由宿主负责；这些不适合由一个通用工具库猜测。

## GitHub 参考与选型

核查日期：2026-09-08。以下是设计借鉴，不是源码审计或版本升级建议；未复制上游实现、未新增依赖。后续采用上游代码必须核对版本兼容及许可证。

| 一手来源 | 可借鉴能力 | 当前项目如何采用 |
| --- | --- | --- |
| [Element Plus](https://github.com/element-plus/element-plus) | Vue3 组件与既有生态 | 延续现有库，先验证版本支持的 API |
| [VueUse](https://github.com/vueuse/vueuse) | 可组合的 Vue 工具组织方式 | 优先已有 composable，确有缺口再评估依赖 |
| [shadcn/ui](https://github.com/shadcn-ui/ui) | 可维护、可拥有的组件代码分发 | 借鉴按需沉淀，不能直接把 React 示例塞进 Vue |
| [Radix 可访问性文档](https://www.radix-ui.com/primitives/docs/overview/accessibility) | 语义、键盘与焦点管理 | 用作交互验收维度，不替换 Element Plus |

## 验收记录模板

| 检查项 | 基线证据 | 修改后证据 | 状态/限制 |
| --- | --- | --- | --- |
| 主流程与错误恢复 | 测试名/实际结果 | 测试名/实际结果 | 完成/部分/未验证 |
| 文档和局部溢出 | 尺寸、元素、截图 | 同条件对照 | 有意滚动单独记录 |

| 键盘与文字缩放 | 路径和截图 | 人工/浏览器结果 | 不声称全面合规 |
| 构建与性能 | 命令、产物、环境 | 同条件测量 | 模拟环境不等于真实用户数据 |
