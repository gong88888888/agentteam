# 02 · 用户、场景与旅程分析（第一章 / MVP）

> 角色：user-researcher。输入：product 第一章/MVP 产品基准（SRC-001~SRC-022）。
> 纪律：事实引用 SRC-###；无法引用者标为【假设】。本文不编造用户研究数据。

## 1. 目标用户与 JTBD

### 1.1 文档给出的定位（事实）
- 一句话：'适合下班后单人刷两层、朋友来了同屏打 Boss 的 PC 横版房间制迷宫刷装游戏'（SRC-002）。
- MVP 范围：第一章 5 层、3 职业、20 怪、1 Boss、50 装备、单人 + 本地同屏 2 人、存档、背包、强化、商店、篝火（SRC-002）。
- 硬约束：单人离线完整可通关为第一优先级；多人仅缩放与协作，不设人数专属门/机关/剧情（SRC-001/SRC-003 NG-4）。

### 1.2 用户分层（【假设】，文档未显式定义）
文档未给出用户画像、动机、替代方案。以下为基于定位的推断，需产品确认：

| 用户类型 | 场景 | JTBD | 当前替代方案【假设】 | 切换动机【假设】 |
|---|---|---|---|---|
| U1 碎片时间单人刷装者 | 下班后 15-30 分钟单局（SRC-020 单局时长目标） | 在有限时间内获得可感知的装备成长与一次完整 run 的收束感 | Hades / Dead Cells / 吸血鬼幸存者类 | 横版房间制 + 明确 Boss 收束 + 低上手门槛 |
| U2 朋友同屏协作玩家 | 朋友到访，本地同屏 2 人打 Boss（SRC-002/SRC-019） | 无需账号/网络即可与身边人共同完成一次 Boss 挑战 | 同屏合作动作游戏 | 即插即用、无人数专属门槛（NG-4） |

> 缺口：U1/U2 的比例、留存预期、流失点均无文档依据；SRC-020 的'本地多人使用率>25%'是唯一相关量化目标，但无运行证据。

## 2. 关键场景与旅程

### 2.1 单人主旅程（BOOT→…→TOWN，SRC-004/SRC-005）
1. 启动→主菜单：继续/新游戏/多人/设置/退出（SRC-006）。无存档时'继续'置灰。
2. 选职业/难度：剑士/法师/游侠，简单/普通/困难，同屏人数 1 或 2（SRC-007）。
3. 层加载：<2s 目标，超时>5s 提示重试/回主菜单（SRC-008）。
4. 迷宫循环：8-12 房间 + 1 Boss 房；每层固定 1 篝火、1 商店；精英 60%；宝箱 2-4；钥匙门≤1（SRC-009）。
5. 战斗与掉落：品质权重白40/绿30/蓝20/紫8/橙2；Boss 保底蓝、紫20%、橙5%（SRC-010）。
6. 商店/篝火/事件：事件二次确认不可撤销（SRC-011）。
7. Boss 房：三阶段、明确前摇；多人血量+10%（SRC-012）。
8. 结算→回城：分解/强化/重铸/换装/接委托/下一层（SRC-013/SRC-014）。

### 2.2 关键时刻（Moment of Truth）
| 时刻 | 文档依据 | 用户风险 |
|---|---|---|
| 首件蓝装（≤10min 目标） | SRC-020 | 无运行证据；若超时，碎片时间用户可能首局即流失 |
| 首个精英/Boss（≤30min 目标） | SRC-020 | 同上 |
| 首次死亡→复活币→回城 | SRC-009/SRC-021 | 复活币未定义（UR-4），回城中断 run |
| 首次回城面对强化/重铸/分解 | SRC-014 | 无引导定义，背包 60 格易满（UR-7） |
| 首次事件不可撤销选择 | SRC-011 | 信息披露不足（UR-8） |
| 2 人掉队/倒地 | SRC-009/SRC-016 | 传送/扶起规则有，但镜头与提示未定义（UR-6） |

### 2.3 双人协作旅程（本地同屏 2 人）
- 入口：主菜单'多人'→CHAR_SETUP 同屏 2 人（SRC-006/SRC-007）。
- 缩放：2 人怪血×1.6、伤害×1.15、金币×1.25、Boss+10% 血（SRC-019）。
- 协作：金币/材料共享，装备独立掉落各自光柱（SRC-010）；倒地 3 秒扶起，全员倒地回城（SRC-016）。
- 存档：主机存世界进度，客机存自身角色；主机可切回单人继续（SRC-015/SRC-019）。
- 缺口：同屏镜头策略、设备分配、客机角色在主机存档中的展示未定义（UR-6/UR-12）。

## 3. 痛点与失败恢复（用户视角）

| 场景 | 文档恢复策略 | 用户影响 | 缺口 |
|---|---|---|---|
| 单人死亡 | 回最近篝火，消耗复活币（SRC-009/SRC-021） | run 中断 | 复活币来源/数量未定义（UR-4） |
| 多人倒地 | 3 秒扶起，否则回篝火（SRC-016） | 协作压力 | 扶起中断进度重置已定义，但提示未定义 |
| 全员倒地 | 回城保留装备（SRC-009） | run 结束 | 回城后引导未定义 |
| 掉队 | 3 秒传送队友（SRC-009） | 节奏打断 | 镜头/提示未定义（UR-6） |
| 卡死房间 | 重置本层保留装备（SRC-009） | 节奏打断 | 保留边界未说明（UR-5） |
| 存档损坏 | 加载备份+CRC 提示（SRC-006/SRC-015） | 信任受损 | 介质未定（SRC-022） |
| 加载超时 | 重试/回主菜单（SRC-008） | 等待焦虑 | 阈值 5s 已定义 |
| 未捕获异常 | 回最近篝火保留日志（SRC-018） | 白屏恐惧 | 判定树未定义（UR-10） |

## 4. 假设清单（需验证，不得当作事实）
- H1【假设】U1 单局 15-30 分钟可完成且不产生'太短/太长'抱怨（对应 SRC-020，无证据）。
- H2【假设】新手 10 分钟内获得首件蓝装足以形成正反馈（SRC-020，无证据）。
- H3【假设】本地同屏 2 人无需教程即可理解缩放与独立掉落（SRC-010/SRC-019，无证据）。
- H4【假设】'事件不可撤销+二次确认'不会造成负面情绪（SRC-011，无证据）。
- H5【假设】复活币机制不会导致碎片时间用户因'无币回城'流失（SRC-009，无证据）。
- H6【假设】主机切回单人继续（SRC-019）不会造成客机角色数据困惑（无证据）。
