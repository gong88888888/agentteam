# 06 技术可行性评审（第一章 / MVP）

> 角色：tech-feasibility。输入为第一章/MVP 产品基准（SRC-001~SRC-022）及前序角色摘要。本文评估技术栈一致性、依赖、性能、安全、成本与前置验证假设。

## 0. 结论摘要

- 硬约束“单人离线完整可通关”在技术层面**无结构性阻断**，但存在 3 项高严重度前置问题需在实现前拍板：
  1. **存档介质未定**（TF-1，SRC-015/SRC-022）：直接决定 S10 读档成功率、双备份+CRC、版本迁移能否实现。
  2. **量化指标无测量方法**（TF-2，SRC-020）：全部验收指标当前不可技术验收。
  3. **多人表含 3/4 人档位**（TF-3，SRC-019 vs SRC-002/SRC-003）：超出 MVP 范围，膨胀测试矩阵。
- 中严重度 7 项集中在数据建模缺口（复活币、房间持久化术语、Boss 阶段状态机、保底掉落异常路径、强化/重铸数值、输入抽象层）。
- 低严重度 3 项为性能/日志/多人存档合并的工程细节。

## 1. 技术栈与基座一致性

- 文档未声明引擎/运行时（SRC-001~SRC-022 均未出现技术栈描述）。基座 `core.js/main.js` 的状态切换与输入事件接口签名列为待确认（SRC-022）。
- **假设（未验证）**：项目为 Web/JS 运行时（由 SRC-022 提及 localStorage/IndexedDB 推断）。此假设需在实现前由基座代码确认。
- 顶层状态机（SRC-004）为 13 状态 + 旁路，适合用显式状态机实现；建议状态转移表数据化，便于测试。

## 2. 数据与存档依赖（最高风险域）

### 2.1 存档介质（TF-1，高）
- 需求：双备份 + CRC 校验、版本迁移、异常退出回最近篝火、读档成功率 >99.5%（SRC-015）。
- localStorage 为同步 API、容量约 5MB、无事务，难以原子写双槽；IndexedDB 支持事务与更大容量。
- 建议：IndexedDB 主存档 + localStorage 轻量设置；写入模式“写临时槽→CRC 校验→切换指针”；schema 带 version 字段与迁移函数。
- 回滚路径：若 IndexedDB 不可用，降级为单槽 localStorage 并提示“存档保护降级”，同时保留最近一次成功快照。

### 2.2 存档字段建模（TF-5/TF-6，中）
- 需显式建模：角色属性、背包（60）、仓库（200）、装备、金币、任务、seed、roomGraph、visitedRooms、clearedRooms、openedDoors、bossState、设置、version（SRC-015）。
- 术语统一：区分“已探索/已清怪/已开门”，避免读档语义歧义（TF-6）。
- 复活币字段缺失（TF-5），需补入 schema 与获取途径。

### 2.3 多人存档归属（TF-13，低）
- 主机存世界进度、客机存自身角色（SRC-019）；需定义合并/只读规则，防止覆盖。

## 3. 生成器与流程不变量

- 房间生成不变量（SRC-009）：每层 1 篝火、1 商店、精英 60%、宝箱 2-4、钥匙门 ≤1、入口到 Boss 主路径连通。
- 风险：钥匙门无保底（TF-4），精英未刷出/事件未给钥匙可致卡死。建议生成后做连通性 + 钥匙可达性静态校验，失败则重生成。
- 卡死检测（SRC-021）需扩展判定条件并保留装备重置本层。

## 4. 战斗、掉落与结算

- 掉落权重（白40/绿30/蓝20/紫8/橙2，Boss 保底蓝、紫20%、橙5%）可数据化并加自动化断言（SRC-010）。
- 异常路径“跳过掉落”会破坏 Boss 保底（TF-8），建议保底走重试队列，S8 结算校验一致性（SRC-013）。
- 多人缩放：MVP 仅实现 1/2 人系数（×1.0/×1.6 血、×1.15 伤、×1.25 金币、Boss +10%），3/4 人移出 MVP（TF-3）。

## 5. Boss 阶段与恢复

- 三阶段 + 30s 超时兜底 + 崩溃回 Boss 前存档点（SRC-012/SRC-021）需显式状态机（TF-7）；恢复点粒度定义为 preFight，避免半阶段恢复。

## 6. 性能目标

- 房间加载 <2s、加载超时 >5s（SRC-008）缺实现路径（TF-11）。建议预加载 + 异步加载边界，定义计时起点，纳入本地基准测量。
- 单局 15-30min、全流程 15-25h（SRC-020）为体验指标，非技术性能门槛，但需埋点支撑测量。

## 7. 安全与合规

- 离线单机、无服务端权威、无反作弊（SRC-003 NG-5）。安全面主要为存档完整性与崩溃不丢档：CRC + 双备份 + 版本迁移（SRC-015）。
- 无内购/广告（NG-6），无隐私上报需求；若做遥测需明确本地优先、可选上报。

## 8. 成本与工作量提示

- 高成本项：存档系统（介质+迁移+双备份）、输入抽象层（本地同屏 2 人）、生成器不变量校验、Boss 状态机。
- 可裁剪项：3/4 人缩放（移出 MVP）、云存档/远程同乐（NG-2/NG-3）。

## 9. 前置验证清单（实现前必须完成）

1. 确认基座 core.js/main.js 状态切换与输入事件接口签名（SRC-022）。
2. 拍板存档介质并做容量/写入耗时实测（TF-1）。
3. 确认本地同屏输入抽象层是否存在（TF-10）。
4. 定义量化指标测量方法与埋点（TF-2）。
5. 定义存档 schema（含复活币、房间持久化字段、version）（TF-5/TF-6）。
6. 定义 Boss 三阶段状态机与恢复点（TF-7）。
7. 定义强化/重铸数值表（TF-9）。
