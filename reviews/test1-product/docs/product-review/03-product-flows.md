# 03 产品流程架构分析（第一章 / MVP）

> 角色：flow-architect。输入：product 产品基准（SRC-001~SRC-022）与前序 product-lead / doc-analyst / user-researcher 摘要。本文把产品方案转成状态机，逐状态给事件、转移、前置条件、失败/恢复、空/加载/错误状态，并列出流程缺口。

## 0. 覆盖与方法

- 覆盖章节：22/22（SRC-001~SRC-022）。
- 方法：以 SRC-004 顶层状态机为骨架，逐状态（SRC-005~SRC-018）抽取状态、事件、转移、前置条件、失败恢复；用 SRC-019 多人规则、SRC-020 量化指标、SRC-021 失败恢复总表做交叉校验。
- 证据纪律：每条事实标注 SRC；无法引用处标为假设。

## 1. 顶层状态机（重建）

```
BOOT → MAIN_MENU → CHAR_SETUP → RUN_LOADING → DUNGEON_LOOP ⇄ BOSS_ROOM → RESULT → TOWN
                                                                          TOWN → RUN_LOADING（下一层，缺口 FA-1）
                                                                          TOWN → MAIN_MENU
旁路：PAUSE（任一游戏内状态可入，返回原状态）、SAVE_LOAD（旁路，不改变主链）、ERROR_RECOVERY（任一状态异常）
```

来源：SRC-004。缺口：TOWN→下一层的目标状态未定义（FA-1）。

## 2. 逐状态定义

### S1 MAIN_MENU（SRC-006）
- 状态：主菜单。
- 事件/输入：继续、新游戏、多人、设置、退出。
- 前置条件：继续仅在有存档时可用。
- 转移：继续→RUN_LOADING；新游戏→CHAR_SETUP；多人→CHAR_SETUP（2 人）。
- 空状态：无存档→继续置灰+提示“暂无存档”。
- 错误状态：CRC 失败→提示“存档损坏，已回退备份”并加载备份槽。
- 恢复：备份加载失败时无定义（FA-10）。

### S2 CHAR_SETUP（SRC-007）
- 事件/输入：职业（剑士/法师/游侠）、难度（简单/普通/困难）、人数（1/2）、确认/返回。
- 前置条件：必须选职业，否则确认置灰；难度默认普通。
- 转移：确认→RUN_LOADING；返回→MAIN_MENU。
- 缺口：人数上限 2 与 SRC-019 的 3/4 人档位冲突（FA-2）。

### S3 RUN_LOADING（SRC-008）
- 事件：自动加载。
- 转移：完成→DUNGEON_LOOP（入口房间）。
- 加载状态：目标 <2s；超时 >5s→提示“加载失败，重试/回主菜单”。
- 错误状态：地图种子缺失→新种子重生成并提示。
- 缺口：加载粒度（整层 vs 逐房间）未定义（FA-11）；与 ERROR_RECOVERY 边界未定义（FA-14）。

### S4 DUNGEON_LOOP（SRC-009）
- 状态：迷宫循环，8-12 房间 + 1 Boss 房。
- 房间类型：战斗、平台跳跃、宝箱、商店、篝火、事件、精英、Boss。
- 生成不变量：每层 1 篝火、1 商店；精英 60%；宝箱 2-4；钥匙门 ≤1 且钥匙由精英/事件给；入口到 Boss 必有主路径。
- 事件/输入：移动、跳跃、普攻、重击、闪避、2 技能、喝药、交互。
- 转移：清怪/交互开门→下一房间；进 Boss 房→BOSS_ROOM；篝火快速回城→TOWN。
- 失败/恢复：
  - 单人死亡→回最近篝火，消耗复活币（无币回城保留装备）。
  - 多人倒地→队友 3s 内扶起；全员倒地→回城。
  - 掉队→3s 传送队友身边。
  - 卡死（无门可开且无怪）→“重置本层”，保留装备。
- 缺口：钥匙门在无精英/事件未给钥匙时不可开（FA-4）；复活币无定义（FA-5）；房间持久化术语不一（FA-6）；卡死检测未覆盖“有门无钥匙”（FA-4）。

### S5 战斗与掉落（SRC-010，DUNGEON_LOOP 子流程）
- 事件：攻击/技能/闪避/喝药。
- 规则：受击闪白、顿帧 80ms、轻震、掉落光柱；品质权重白40/绿30/蓝20/紫8/橙2；Boss 保底蓝、紫20%、橙5%；装备 2-4 词条。
- 多人：金币/材料共享；装备独立掉落。
- 错误状态：掉落生成异常→跳过并记录日志，不阻塞开门。
- 缺口：跳过保底掉落破坏 S8 一致性验收（FA-8）。

### S6 商店/篝火/事件（SRC-011）
- 商店：买药、钥匙、随机装备；金币不足置灰。
- 篝火：回血、存档、复活队友、快速回城。
- 事件：赌装备、诅咒/祝福、NPC 委托；选择不可撤销，需二次确认。
- 错误状态：数据缺失→降级为战斗房并提示。
- 缺口：降级后与“每层 1 商店”不变量冲突（FA-13）。

### S7 BOSS_ROOM（SRC-012）
- 规则：三阶段，明确前摇；多人血量 +10%；仇恨优先最近/伤害最高。
- 转移：击败→RESULT；全员倒地→回城（保留装备）。
- 错误状态：卡阶段→超时 30s 强制下一阶段；Boss 房崩溃→回 Boss 前自动存档点。
- 缺口：超时计时起点与前摇冲突未定义（FA-7）。

### S8 RESULT（SRC-013）
- 事件：确认。
- 展示：装备/金币/材料、用时、击杀数。
- 转移：确认→TOWN。
- 错误状态：结算数据缺失→显示“结算异常”，仍发放已拾取物品。
- 缺口：保底掉落被跳过时结算一致性无法保证（FA-8）。

### S9 TOWN（SRC-014）
- 事件：分解、强化、重铸、换装、接委托、进入下一层、回主菜单。
- 规则：背包 60、仓库 200；强化 +1~+9 失败不掉级但耗材料；重铸随机 1 词条有保底。
- 错误状态：背包满→提示并允许一键分解白绿。
- 缺口：进入下一层的目标状态未定义（FA-1）。

### S10 SAVE_LOAD（SRC-015，旁路）
- 触发：进房间、回城、Boss 前、篝火自动存档；手动存档仅篝火/回城。
- 内容：角色属性、背包、装备、金币、任务、地图种子、已开房间、Boss 状态、设置、版本号。
- 防丢档：双备份 + CRC；异常退出回最近篝火。
- 错误状态：CRC 失败→加载备份；版本不匹配→自动迁移，客机角色只读。
- 缺口：介质未定（FA-3）；PAUSE 存档与手动存档口径冲突（FA-9）；备份也版本不匹配时无兜底（FA-10）。

### S11 双人复活（SRC-016，多人子状态）
- 事件：靠近倒地队友 + 交互键持续 3s。
- 转移：成功→队友恢复部分血量；3s 未扶起→队友回篝火。
- 错误状态：扶起中断（受击/离开）→进度重置。
- 缺口：与单人死亡路径的分支判定未显式化（FA-12）。

### S12 PAUSE（SRC-017）
- 事件：继续、设置、回主菜单（提示未存档进度）。
- 恢复：回主菜单前自动存档一次。
- 缺口：与 S10 手动存档口径冲突（FA-9）。

### S13 ERROR_RECOVERY（SRC-018）
- 触发：未捕获异常、资源加载失败、存档损坏。
- 行为：提示 + 回最近篝火或主菜单；保留现场日志。
- 验收：不白屏、不丢档。
- 缺口：与 S3 加载失败重试边界未定义（FA-14）。

## 3. 多人缩放与状态可达性

- 表（SRC-019）：1/2/3/4 人血量 ×1.0/×1.6/×2.1/×2.6，伤害 ×1.0/×1.15/×1.25/×1.35，金币 ×1.0/×1.25/×1.45/×1.65，Boss 额外 +10%。
- 可达性：MVP 仅 1/2 人（SRC-002、SRC-007），3/4 人档位无对应状态入口（FA-2）。
- 存档归属：主机存世界进度，客机存自身角色；多人存档可切回单人（SRC-019）。

## 4. 失败恢复总表（对齐 SRC-021）

| 场景 | 恢复策略 | 状态机落点 | 缺口 |
|---|---|---|---|
| 单人死亡 | 回最近篝火，消耗复活币 | DUNGEON_LOOP | 复活币未定义（FA-5） |
| 多人倒地 | 3s 扶起，否则回篝火 | S11 | 分支判定（FA-12） |
| 全员倒地 | 回城，保留装备 | DUNGEON_LOOP→TOWN | — |
| 掉队 | 3s 传送队友 | DUNGEON_LOOP | — |
| 卡死房间 | 重置本层，保留装备 | DUNGEON_LOOP | 未覆盖有门无钥匙（FA-4） |
| 存档损坏 | 加载备份 + CRC 提示 | SAVE_LOAD | 备份也损坏/版本不匹配（FA-10） |
| 版本不匹配 | 自动迁移 / 客机只读 | SAVE_LOAD | 迁移失败兜底（FA-10） |
| 加载超时 | 重试或回主菜单 | RUN_LOADING | 粒度（FA-11） |
| 未捕获异常 | 回最近篝火，保留日志 | ERROR_RECOVERY | 与 S3 边界（FA-14） |

## 5. 流程缺口清单（按严重度）

高：FA-1（TOWN→下一层转移缺失）、FA-2（3/4 人档位不可达）、FA-3（存档介质未定阻塞 SAVE_LOAD 恢复路径）。
中：FA-4（钥匙门卡死）、FA-5（复活币未定义）、FA-6（房间持久化术语不一）、FA-7（Boss 超时口径）、FA-8（保底掉落被跳过）、FA-9（PAUSE 存档口径）。
低：FA-10（备份+版本双失败兜底）、FA-11（加载粒度）、FA-12（死亡分支判定）、FA-13（商店降级与不变量冲突）、FA-14（加载失败与 ERROR_RECOVERY 边界）。

## 6. 对现有版本/数据/契约/用户的影响与回滚

- 本章为 MVP 基准，无既有线上版本；影响面为存档契约与状态机契约。
- 存档契约：若先按 localStorage 实现后改 IndexedDB，需迁移层；建议先拍板介质（FA-3）再冻结字段（SRC-015）。
- 状态机契约：TOWN→下一层转移（FA-1）与人数上限（FA-2）应在实现前冻结，否则后续改动波及 UI 与存档。
- 回滚路径：状态机与存档字段以版本号（SRC-015）标记，迁移失败回退备份槽（SRC-006/SRC-015）；MVP 无云存档（SRC-003 NG-2），回滚仅限本地双备份。

## 7. 假设

- 假设 A1：RUN_LOADING 为整层加载，逐房间为子加载（SRC-008 未明示）。
- 假设 A2：复活币为角色级资源，随存档持久化（SRC-009 未定义）。
- 假设 A3：PAUSE 退出存档写入独立临时槽（SRC-017 未明示）。
