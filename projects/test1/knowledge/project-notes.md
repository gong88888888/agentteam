# 迷宫冒险家 · 项目知识条目

> 角色：kb（知识沉淀）
> 状态：候选知识（非权威），不修改基准条款与业务资产内容。
> 来源：本次需求文档 + 前置产物摘要（pm/product/ui/arch/backend/frontend/review/qa/security/ops）。

## 1. 产品定位（可复用结论）

- 类型：2D 横版房间制迷宫动作冒险 + 轻刷装 + 本地多人。
- 平台：PC Windows，离线优先，买断制无内购。
- 一句话：单人下班刷两层、朋友来了同屏打 Boss 的横版迷宫刷装游戏。
- **第一优先级：单人离线完整可通关**；本地同屏为差异化卖点；局域网联机列 P1。
- 硬原则：所有 Boss、装备、剧情单人均可获取；不设人数专属门/机关/剧情。

## 2. MVP 边界（与 pm/product 一致）

- 第一章 5 层、3 职业（剑士/法师/游侠）、20 种怪、1 Boss、50 件装备。
- 单人 + 本地同屏 2 人、存档、背包、强化、商店、篝火。
- 局域网联机放 P1，EA 前补；远程同乐不纳入 MVP。
- 交付形态：可运行 `game/index.html`，技术栈固定 HTML5 Canvas + 原生 ES Modules。

## 3. 多人缩放查表（可验证数值，勿改）

| 人数 | 怪物血量 | 怪物伤害 | 金币 |
|---|---|---|---|
| 1 | 1.0 | 1.0 | 1.0 |
| 2 | 1.6 | 1.15 | 1.25 |
| 3 | 2.1 | 1.25 | 1.45 |
| 4 | 2.6 | 1.35 | 1.65 |

- Boss 血量额外 +10%。
- 掉落规则：金币/材料共享拾取；装备独立掉落，按玩家 id 哈希分桶，每人只见自己的光柱。
- 复活：单人死亡回篝火/消耗复活币；多人倒地可被队友 3 秒扶起，全员倒地回城。
- 存档归属：主机存世界进度，客机存自身角色；多人存档可由主机切回单人继续。

## 4. 掉落与品质（可验证数值）

- 品质权重：白 40%、绿 30%、蓝 20%、紫 8%、橙 2%。
- Boss 保底：必掉 1 件蓝+；紫 20%、橙 5%。
- 词条：每件 2-4 条（攻击/暴击/攻速/生命/移速/技能冷却/金币获取）。
- 部位：武器、头盔、衣服、鞋子、饰品；武器职业独立，防具通用。
- 强化 +1~+9，失败不掉级但耗材料；重铸随机 1 条词条且有保底。

## 5. 房间生成不变量（生成失败应抛错，不静默）

- 每层 8-12 房间 + 1 Boss 房。
- 主路径从入口到 Boss 必须连通；支路给宝箱/事件。
- 每层恰 1 个篝火、1 个商店；精英房概率 60%；宝箱房 2-4 个。
- 钥匙门每层最多 1 个，钥匙由精英怪/事件房给，保证可达不卡死。
- 随机种子 + 已探索房间记录，读档可恢复。

## 6. 存档契约（SaveEnvelope）

- 含版本号、CRC32 校验、双备份、迁移链。
- 自动存档点：进房间、回城、Boss 前、篝火；手动存档仅篝火/回城。
- 异常退出回最近篝火快照。
- 3 个世界槽；客机角色单独档；版本不匹配时只读提示。
- 云存档 MVP 不做。

## 7. 门禁与角色分工（硬约束）

- 门禁：`node --test game/tests/game_logic.test.mjs` 与 `node game/tests/smoke.mjs` 必须通过。
- 基座文件不得覆盖：`game/js/core.js`、`game/js/main.js`、`game/index.html`、`game/tests/game_logic.test.mjs`、`game/tests/smoke.mjs`。
- 代码角色只写 `game/js/gameplay/` 或 `game/js/ui/` 增量 `.js`；QA 只新增 `game/tests/qa_*.mjs`。
- 角色链：pm → product → ui → arch → backend → frontend → review → qa → security → ops → kb。
- 发布需裁判凭证，脚本不绕过门禁。

## 8. 踩坑与失效条件（何时需重审本条目）

- 失效条件 1：多人缩放数值或掉落权重被产品基准正式修订 → 本表同步更新。
- 失效条件 2：MVP 范围变更（如局域网提前进 MVP）→ 第 2 节重写。
- 失效条件 3：基座 API 变更导致增量模块接口不兼容 → 第 7 节门禁说明需回填实测结果。
- 已知风险：增量模块与基座存在隐式耦合可能破坏基线测试；浏览器存档介质降级未验证；局域网 UDP 在 Canvas 栈不可行需降级。
- 知识纪律：候选知识不得提升为权威；不得删除审计记录；不得修改基准条款。
