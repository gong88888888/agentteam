# 《迷宫冒险家》MVP 发布计划

## 1. 概述
本项目为2D横版房间制迷宫动作冒险游戏，定位为PC Windows平台，离线优先。MVP阶段聚焦于单人完整体验与本地同屏多人增强。

## 2. MVP 范围 (12周)
- **内容**：第一章“蘑菇林迷宫”（5层），3个职业（剑士、法师、游侠），20种怪物，1个Boss，50件装备。
- **功能**：单机完整通关、本地同屏2人、存档系统、背包/强化/商店、篝火机制。
- **排除**：远程联机、无尽模式、图鉴/成就系统（EA阶段补充）。

## 3. 构建与发布流程

### 3.1 构建环境
- **引擎选型待定**：需确认 Unity 或 Godot，以决定 CI/CD 工具链。
- **依赖管理**：ScriptableObject (Unity) 或 ResourceLoader (Godot) 配置化。
- **静态检查**：代码规范、资源命名规范、内存泄漏扫描。

### 3.2 门禁要求 (Gate Check)
1. **技术栈一致性**：验证 React 前端组件与游戏引擎的集成路径，确保无重大重构风险。
2. **存档完整性**：验证 WAL 预写日志与双备份机制，确保异常退出后数据可恢复。
3. **本地多人兼容性**：验证键盘/手柄混用输入映射，确保同屏镜头缩放逻辑正常。
4. **性能基准**：GTX750/集显下稳定 60 FPS，房间加载 < 2s。

### 3.3 发布策略
- **Alpha (内部)**：功能完整，无平衡性要求。重点验证存档与本地多人同步。
- **Beta (封闭测试)**：内容完整，开始数值调优。邀请核心玩家测试掉落体验与难度曲线。
- **EA (抢先体验)**：3章+局域网联机+无尽模式。面向公众开放，收集反馈。

## 4. 监控与回滚

### 4.1 监控指标
- **崩溃率**：< 0.5%。
- **读档成功率**：> 99.5%。
- **单人通关率**：> 35%。
- **本地多人使用率**：> 25%。

### 4.2 回滚方案
- **自动回滚**：若构建失败或门禁未通过，自动触发回滚至上一稳定版本。
- **手动回滚**：EA阶段若出现严重Bug（如存档损坏、无法联机），立即暂停更新，发布热修复补丁或回退至前一版本。
- **数据兼容**：存档系统需支持版本迁移，确保新版本能读取旧版存档。

## 5. 风险与对策
- **技术栈冲突**：早期介入引擎选型，明确 React 组件用途（如编辑器工具），避免运行时集成难题。
- **内容量不足**：通过房间模板组合、词条随机化、无尽模式延长生命周期。
- **存档风险**：实施 WAL + CRC 校验，确保数据原子性与完整性。

## 6. 验收标准
- 新手10分钟内获得第一件蓝装。
- 30分钟内击败首个精英/Boss。
- 单局时长15-30分钟。
- 全流程15-25小时。
