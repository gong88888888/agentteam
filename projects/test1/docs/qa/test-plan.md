# 迷宫冒险家 · QA 测试计划

> 角色：qa ｜ 依据：docs/product/product-baseline.md、docs/plan/project-plan.md、docs/architecture/architecture.md、contracts/openapi.yaml、docs/design/ui-spec.md
> 约束：只新增 game/tests/qa_*.mjs；不修改基座 game/tests/game_logic.test.mjs 与 game/tests/smoke.mjs；不写 src/**。

## 1. 测试目标与范围

### 1.1 目标
- 验证架构契约中的四类核心不变量：战斗缩放、掉落分桶、房间生成、存档完整性。
- 为产品验收指标提供可测化拆解（首蓝装、首Boss、单局时长、读档成功率）。
- 保证基座逻辑测试与 smoke 基线不被破坏。

### 1.2 范围内（MVP）
- 战斗：固定步长确定性 tick、伤害管线顺序、多人缩放查表、Boss 额外 +10% 血量。
- 掉落：品质权重（白40/绿30/蓝20/紫8/橙2）、Boss 保底（蓝保底、紫20%、橙5%）、装备按玩家 id 哈希独立分桶、金币材料共享。
- 房间：主路径连通、每层恰 1 篝火 1 商店、钥匙门 ≤1 且钥匙可达、种子+已探索可恢复。
- 存档：SaveEnvelope 版本号、CRC32、双备份、迁移链、异常退出回最近篝火快照。
- 冒烟：game/index.html 可加载、增量模块可 import、基座测试通过。

### 1.3 范围外（P1/后续）
- 局域网 UDP 联机（Canvas 栈不可行，待架构降级方案）。
- 远程同乐、云存档、交易行。
- 视觉/像素级 UI 回归（由 ui 角色自测，QA 仅做可访问性抽查）。

## 2. 测试策略

| 层级 | 手段 | 覆盖 |
|---|---|---|
| 逻辑单测 | node:test（qa_*.mjs） | 战斗/掉落/房间/存档纯函数不变量 |
| 冒烟 | node game/tests/smoke.mjs（基座，不改） | index.html 可加载 |
| 基线回归 | node --test game/tests/game_logic.test.mjs（基座，不改） | 基座逻辑不回归 |
| 验收 | 手工/脚本化场景 | 产品验收指标 |

**原则**：模块未就绪时测试显式 `skip`，绝不伪造通过；失败保留证据不重试掩盖。

## 3. 用例矩阵

### 3.1 战斗缩放（qa_combat_scaling.test.mjs）
| ID | 用例 | 期望 |
|---|---|---|
| C-01 | 单人缩放 | 血量/伤害/金币系数均 = 1.0 |
| C-02 | 2人缩放 | 血量1.6 伤害1.15 金币1.25 |
| C-03 | 3人缩放 | 血量2.1 伤害1.25 金币1.45 |
| C-04 | 4人缩放 | 血量2.6 伤害1.35 金币1.65 |
| C-05 | Boss 额外血量 | 在人数缩放基础上再 ×1.10 |
| C-06 | 固定步长确定性 | 相同输入序列两次 tick 结果一致 |
| C-07 | 伤害管线顺序 | 基础→词条→暴击→防御→多人缩放→Boss血量 |

### 3.2 掉落分桶（qa_loot_bucket.test.mjs）
| ID | 用例 | 期望 |
|---|---|---|
| L-01 | 品质权重分布 | 大样本下白/绿/蓝/紫/橙比例接近 40/30/20/8/2（容差） |
| L-02 | Boss 保底蓝 | Boss 掉落品质 ≥ 蓝 |
| L-03 | Boss 紫/橙概率 | 紫≈20%、橙≈5%（容差） |
| L-04 | 装备独立分桶 | 不同玩家 id 哈希得到各自掉落，互不可见 |
| L-05 | 金币材料共享 | 共享拾取，不按玩家分桶 |

### 3.3 房间生成不变量（qa_room_invariants.test.mjs）
| ID | 用例 | 期望 |
|---|---|---|
| R-01 | 主路径连通 | 入口到 Boss 房存在可达路径 |
| R-02 | 每层 1 篝火 1 商店 | 计数恰为 1 |
| R-03 | 钥匙门 ≤1 且钥匙可达 | 钥匙门数量 ≤1，钥匙在可达房间 |
| R-04 | 种子可复现 | 同种子生成同结构 |
| R-05 | 已探索恢复 | 种子+已探索集合可恢复地图状态 |
| R-06 | 生成失败抛错 | 非法参数抛错而非静默 |

### 3.4 存档完整性（qa_save_envelope.test.mjs）
| ID | 用例 | 期望 |
|---|---|---|
| S-01 | 版本号存在 | SaveEnvelope 含 version 字段 |
| S-02 | CRC32 校验 | 篡改内容后校验失败 |
| S-03 | 双备份 | 主备份损坏时回退副备份 |
| S-04 | 迁移链 | 旧版本存档可迁移到当前版本 |
| S-05 | 异常退出回篝火 | 未正常保存时恢复到最近篝火快照 |

### 3.5 验收指标拆解
| 指标 | 可测化拆解 | 手段 |
|---|---|---|
| 新手10分钟首蓝装 | 首蓝装掉落时间 ≤10min | 脚本化模拟掉落序列 |
| 30分钟首Boss | 首Boss击败时间 ≤30min | 场景计时 |
| 单局15-30分钟 | 8-12房间+1Boss 通关时长区间 | 场景计时 |
| 读档成功率>99.5% | 1000次读档失败 ≤5 | 循环读档脚本 |
| 崩溃率<0.5% | 会话崩溃计数 | 冒烟+长跑 |

## 4. 执行与证据
- 命令：`node --test game/tests/qa_*.test.mjs`、`node --test game/tests/game_logic.test.mjs`、`node game/tests/smoke.mjs`。
- 证据：测试输出日志、失败用例复现步骤、截图（UI 相关）。
- 缺陷：必须含复现步骤+期望/实际+证据，否则不提交。

## 5. 风险与升级
- 模块导出路径未定 → 测试动态 import 探测，缺失则 skip 并升级集成方。
- 存档介质未定 → 持久化断言待介质确认后补。
- 同类缺陷反复 → 升级 reviewer/judge。
