# AgentTeam

一人公司主导的全栈交付 Agent 集群。当前仓库处于 **v4.1 编排协议预演** 阶段：不调用真实 LLM，先用确定性仿真验证「任务切片 → 工具证据 → 外部裁判 → 门禁凭证 → 复评」是否自洽。

## 快速运行

```bash
python -I sim/dryrun.py        # v4.1：工具证据 + 外部裁判；输出 sim/out/v4/
python -I sim/_baseline_v3.py  # v3 人审批基线；输出 sim/out/human/
python -I specs/validate_specs.py
python -I sim/selfcheck.py       # 编排协议回归自检
```

当前预演结果（单项目、3 切片、4 并发，脚本化裁判桩）：

| 指标 | v3 人审批 | v4.1 外部裁判 |
|---|---|---|
| 虚拟工期 | 1,910 min | 1,252 min（-34%） |
| 人决策 | 7 次 | 0 次 |
| 人等待 | 1,545 min | 0 |
| 裁判等待 | — | 82 min（20 次调用，216K Token，约 $0.25） |
| 门禁首过 | 6/7 = 86% | 3/8 = 38%（更严，见下文） |
| 返工 | 4 | 6（含 2 次补证） |
| 任务 | 52 | 59（成功 56 / 失败 2 / 被取代 1） |
| 证据 | 34 | 80（9 次复用，3 次失效） |
| 缺陷 | 2（致命 1） | 2（致命 1，全部闭环） |

首过率下降不是质量变差：v4.1 在架构门禁要求补 auth 威胁模型、验收门禁要求补回滚演练、发布门禁强制重跑 SAST/E2E，并在 D-101 修复后强制 `s2_regate`。这些都是 v4.0 预演里没有真正验证的路径。

## 目录

```
docs 设计基线（agentteam1/2、v3、v4、落地参考）
specs/                机器可校验契约：任务卡、证据、决策包、裁决、12 份 Agent 规格
sim/                  确定性编排预演（v4.1），v4.0 备份在 dryrun_v4.0.py
sim/out/v4/           v4.1 事件账本、时间线、指标、自动报告
sim/out/human/        v3 人审批基线产物
config/               配置示例（只放环境变量名，不含密钥）
```

## 当前边界

- 裁判是脚本化 rubric 桩，不是真实 DeepSeek 调用；上述数字证明流程结构，不证明裁判准确率。
- 真实接入前必须用金标准集测漏判率/误批率；模型裁判不能推翻确定性失败、缺失/未签名证据、高危漏洞、无回滚发布。
- 医疗、金融持牌等要求人工签核的场景不适用本方案。
- 运行时沙箱、真实 CI、真实 deepseekharness 适配器仍是下一步（W1）。
